# HoloBoxing 最小仿真复现

本机已验证配置和算法张量链路，在 WSL2 完成单进程数据采集、1 轮先验、1 轮监督模仿和 1 次站立预热 PPO 更新。导出的高层 ONNX 已通过官方 v12 的接口与单次 CUDA 推理校验。 [本机实测](../results/README.md) · [v12 校验结果](../results/v12-validation.json)

## 本地复查配置

以下命令从项目根目录运行。先激活已有 PyTorch 的 Python 3.11 环境。官方 `TrainConfig` 读取配置后会检查动作接口、rollout 与 minibatch 的整除关系以及 AMP 批大小。

```powershell
Set-Location (Join-Path (Get-Location) 'upstream/HoloMotion')

cfg = TrainConfig(**json.loads(Path("../../configs/rl-smoke.json").read_text()))
print(cfg.num_envs, cfg.num_steps_per_env, cfg.num_mini_batches)
'@ | & $holoCheckPython -B -
```

## 下一阶段的最小规模

| 设置 | 本项目小配置 | 官方教程 |
| --- | --- | --- |
| 网络宽度 | Actor、Critic 隐藏层 `[256,128]`，AMP 为 `[128,64]` | 同左 |
| 每次更新采样 | 4 个并行环境，每环境 8 步，学习方 32 条名义转移 | 128 个环境，每环境 24 步，学习方 3,072 条名义转移 |
| PPO 与 AMP | 每次更新 1 轮、2 个 minibatch，AMP batch 16、replay 容量 256 | 每次更新 5 轮、4 个 minibatch，AMP batch 128、replay 容量 16,384 |
| 训练长度 | 先验和 SL 各 1 轮，站立预热 1 次 RL 更新。自博弈 2 次更新，以覆盖一次快照刷新边界 | 先验按验证提前停止，SL 20 轮，站立预热 32 次，自博弈 128 次 |
| 初始探索标准差 | 站立预热与自博弈均为 0.1 | 站立预热 0.1，自博弈 0.2 |

`rl-smoke.json` 由官方 `sample.json` 的网络与探索设定缩小采样和更新规模，其余由官方 `training.json` 提供默认值。三段均复用官方训练入口，底层模型按冻结清单加载。两阶段 RL 命令都显式给出更新数。 [小配置](../configs/rl-smoke.json) · [官方 sample.json](https://github.com/HorizonRobotics/HoloMotion/blob/f52dd81ae935a828b0296f5ee0f833beb7378bf0/holoboxing/training/configs/sample.json) · [官方 RL 参数](https://github.com/HorizonRobotics/HoloMotion/blob/f52dd81ae935a828b0296f5ee0f833beb7378bf0/holoboxing/training/train_rl.py#L17)

## 1. Linux 源码与依赖

在已有 NVIDIA GPU 的 Linux x86-64 环境准备 Python 3.11、`venv`、Git LFS 和支持 CUDA 12.8 的驱动。从本项目根目录运行以下命令。训练源码和工作目录使用 Linux 文件系统，以便 Git 正常创建符号链接。已有同一完整提交的 Linux 检出时，可复用它作为 `HOLOBOXING_SOURCE`。

```bash
export HOLOBOXING_PROJECT="$(pwd -P)"
export HOLOBOXING_WORK="$HOME/holoboxing-sim"
export HOLOBOXING_SOURCE="$HOLOBOXING_WORK/HoloMotion"
export HOLOBOXING_SMOKE_CFG="$HOLOBOXING_PROJECT/configs/rl-smoke.json"
export HOLOMOTION_REV=f52dd81ae935a828b0296f5ee0f833beb7378bf0
export GIT_LFS_SKIP_SMUDGE=1
export CUDA_VISIBLE_DEVICES=0

test -r "$HOLOBOXING_SMOKE_CFG"
python3.11 --version
git lfs version
nvidia-smi
mkdir -p "$HOLOBOXING_WORK"
git clone --depth 1 --filter=blob:none --sparse \
  https://github.com/HorizonRobotics/HoloMotion.git "$HOLOBOXING_SOURCE"
cd "$HOLOBOXING_SOURCE"
if ! git cat-file -e "${HOLOMOTION_REV}^{commit}"; then
  git fetch --depth 1 --filter=blob:none origin "$HOLOMOTION_REV"
fi
git checkout --detach "$HOLOMOTION_REV"
git sparse-checkout set --skip-checks holoboxing holoretarget holosmpl \
  holomotion/src/motion_tracking holomotion/src/modules holomotion/src/utils \
  holomotion/src/training thirdparties/HoloMotion_assets
git rev-parse HEAD

python3.11 -m venv .venv-holoboxing
source .venv-holoboxing/bin/activate
python -m pip install torch==2.9.1 --index-url https://download.pytorch.org/whl/cu128
python -m pip install -r holoboxing/training/requirements.txt
python -m pip check
python - <<'PY'
import torch
import onnxruntime as ort
import warp as wp

assert torch.cuda.is_available()
print(torch.__version__, torch.version.cuda, torch.cuda.get_device_name(0))

```

已准备相同提交的 Linux 检出时，从激活训练环境的步骤继续即可。上面的探测确认设备、CUDA 张量执行与 provider 枚举，冻结 ONNX 的真实会话将在数据采集阶段验证。 [训练依赖](https://github.com/HorizonRobotics/HoloMotion/blob/f52dd81ae935a828b0296f5ee0f833beb7378bf0/holoboxing/training/requirements.txt)

## 3. 下载小样本并生成参考与实测训练记录

把 `HOLOBOXING_SMPL` 设置为已获授权的中性 SMPL 文件。下例用官方教程挑选的 RoboStriker 原动作组和 InterHuman clip ID。后者保留官方划分。两个数据准备命令使用同一随机种子和划分比例。

```bash
export HOLOBOXING_RUN="$HOLOBOXING_WORK/runs/$(date -u +%Y%m%dT%H%M%SZ)"
export HOLOBOXING_SMPL=/absolute/path/to/licensed/neutral-smpl.pkl
test -r "$HOLOBOXING_SMPL"
mkdir -p "$HOLOBOXING_RUN"

python -m holoboxing.data download robostriker \
  --output "$HOLOBOXING_RUN/robostriker" --limit-groups 4 --workers 2
python -m holoboxing.data download interhuman \
  --output "$HOLOBOXING_RUN/interhuman" \
  --clip-id 1124 --clip-id 1843 --clip-id 4033 --workers 2

python3.11 -m venv .venv-holoboxing-retarget
.venv-holoboxing-retarget/bin/python -m pip install torch==2.9.1 \
  --index-url https://download.pytorch.org/whl/cu128
.venv-holoboxing-retarget/bin/python -m pip install -r holoboxing/data/retarget-requirements.txt
.venv-holoboxing-retarget/bin/python -m pip check
.venv-holoboxing-retarget/bin/python -m holoboxing.data retarget \
  --source "$HOLOBOXING_RUN/interhuman" --output "$HOLOBOXING_RUN/interhuman-g1" \
  --smpl-model "$HOLOBOXING_SMPL" --assets "$HOLOBOXING_ASSETS" --device cuda:0 --iterations 4

python -m holoboxing.training.prepare_prior \
  --source "$HOLOBOXING_RUN/robostriker" --source "$HOLOBOXING_RUN/interhuman-g1" \
  --assets "$HOLOBOXING_ASSETS" --output "$HOLOBOXING_RUN/reference" \
  --seed 42 --validation-fraction 0.1 --test-fraction 0.1
python -m holoboxing.data prepare \
  --source "$HOLOBOXING_RUN/robostriker" --source "$HOLOBOXING_RUN/interhuman-g1" \
  --assets "$HOLOBOXING_ASSETS" --output "$HOLOBOXING_RUN/measured" \
  --seed 42 --validation-fraction 0.1 --test-fraction 0.1 --workers 1
python -m holoboxing.data verify --output "$HOLOBOXING_RUN/measured" --assets "$HOLOBOXING_ASSETS"
test -s "$HOLOBOXING_RUN/measured/COMPLETE.json"
export HOLOBOXING_DATA="$HOLOBOXING_RUN/measured/prepared"
```

`prepare_prior` 使用源轨迹和 CPU 正运动学生成参考目标。`data prepare` 调用 CUDA 场景与底层控制器生成实测观测、监督目标及 AMP 所需记录，并通过 `HOLOBOXING_LOWER` 找到冻结模型。两路产物通过各自的清单传给后续入口。三路数据划分至少需要三个 RoboStriker 原动作组，并保留同组原动作及镜像。SL 入口读取 InterHuman 训练划分。 [分组与实测准备](https://github.com/HorizonRobotics/HoloMotion/blob/f52dd81ae935a828b0296f5ee0f833beb7378bf0/holoboxing/data/prepare.py#L61) · [实测资源装配](https://github.com/HorizonRobotics/HoloMotion/blob/f52dd81ae935a828b0296f5ee0f833beb7378bf0/holoboxing/data/records.py#L425) · [参考位姿窗口](https://github.com/HorizonRobotics/HoloMotion/blob/f52dd81ae935a828b0296f5ee0f833beb7378bf0/holoboxing/training/prepare_prior.py#L22)

本机使用 `uv` 安装时，Chumpy 的旧构建脚本在隔离构建环境中缺少 `pip`。已在重定向虚拟环境先装 `pip setuptools wheel`，再用 `uv pip install --no-build-isolation-package chumpy -r holoboxing/data/retarget-requirements.txt` 完成安装。WSL2 的 7.5 GiB 主存与 2 GiB 交换空间下，首次两次采集均触发 OOM。复测对采集进程采用 glibc 内存分配参数，并在独立进程生成 PPO 所需的 ONNX 运行图，完成了单进程采集、监督模仿及 4 环境的一次 PPO 更新。 [内存参数与实测记录](../results/README.md#本机内存与运行图)

## 4. 一轮模仿初始化、最小 RL 与导出

```bash
python -m holoboxing.training.train_prior \
  --data "$HOLOBOXING_RUN/reference" --output "$HOLOBOXING_RUN/prior" \
  --hidden-dims 512 256 --epochs 1 --batch-size 256 --seed 43 --device cuda:0
test -s "$HOLOBOXING_RUN/prior/best.pt"

python -m holoboxing.training.train_sl \
  --assets "$HOLOBOXING_ASSETS" --lower "$HOLOBOXING_LOWER" \
  --data "$HOLOBOXING_DATA" --prior-checkpoint "$HOLOBOXING_RUN/prior/best.pt" \
  --config "$HOLOBOXING_SMOKE_CFG" --output "$HOLOBOXING_RUN/sl" \
  --epochs 1 --batch-size 128 --seed 43 --device cuda:0
test -s "$HOLOBOXING_RUN/sl/epoch_000001.pt"

python -m holoboxing.training.train_rl \
  --assets "$HOLOBOXING_ASSETS" --lower "$HOLOBOXING_LOWER" --amp-motions "$HOLOBOXING_DATA" \
  --supervised-checkpoint "$HOLOBOXING_RUN/sl/epoch_000001.pt" \
  --config "$HOLOBOXING_SMOKE_CFG" --training-mode standing --updates 1 \
  --output "$HOLOBOXING_RUN/warmup" --device cuda:0
test -s "$HOLOBOXING_RUN/warmup/model_1.pt"

python -m holoboxing.training.train_rl \
  --assets "$HOLOBOXING_ASSETS" --lower "$HOLOBOXING_LOWER" --amp-motions "$HOLOBOXING_DATA" \
  --policy-checkpoint "$HOLOBOXING_RUN/warmup/model_1.pt" \
  --config "$HOLOBOXING_SMOKE_CFG" --training-mode selfplay --updates 2 \
  --opponent-pool-capacity 2 --opponent-refresh-updates 1 \
  --output "$HOLOBOXING_RUN/selfplay" --device cuda:0
test -s "$HOLOBOXING_RUN/selfplay/model_2.pt"

python -m holoboxing.training.export \
  --checkpoint "$HOLOBOXING_RUN/selfplay/model_2.pt" --output "$HOLOBOXING_RUN/boxing.onnx"
```

第一次运行会编译 Warp 内核，也会加载并校验冻结模型。数据与显存预算较小时，先在 CUDA 主机完成实测采集，然后可把 `train_prior` 和 `train_sl` 的 `--device` 改为 `cpu`。SL 仍读取实测数据、资产和底层元数据。导出使用 CPU 对照 PyTorch 和 ONNX 输出。 [先验训练](https://github.com/HorizonRobotics/HoloMotion/blob/f52dd81ae935a828b0296f5ee0f833beb7378bf0/holoboxing/training/train_prior.py#L302) · [高层导出](https://github.com/HorizonRobotics/HoloMotion/blob/f52dd81ae935a828b0296f5ee0f833beb7378bf0/holoboxing/training/export.py#L151)

小配置链路的验收依据是数据 `COMPLETE.json`、先验 `best.pt`、SL 完整轮次检查点，以及两段 RL 的 `training-result.json`。预热和自博弈的 `progress.completed_updates` 应分别为 1 和 2，`metrics.jsonl` 应记录有限的 `ego/surrogate`、`ego/value` 和 `amp/loss`。自博弈在第二次采集前将新的 Actor 快照加入池，可从检查点追踪快照状态。成功导出说明该小样本链路可以执行。策略质量、显存与速度均需另行实测。 [训练结果记录](https://github.com/HorizonRobotics/HoloMotion/blob/f52dd81ae935a828b0296f5ee0f833beb7378bf0/holoboxing/training/checkpoint_io.py#L65) · [对手池](https://github.com/HorizonRobotics/HoloMotion/blob/f52dd81ae935a828b0296f5ee0f833beb7378bf0/holoboxing/training/opponent_pool.py#L56)

## 6. 初赛训练路线

以 **首场完整仿真对战 → 自博弈小测 → 参考基线 → 候选选型** 为顺序。现有数据有 8 个实测片段和 11,462 条观测目标样本，其中实际用于监督训练的 InterHuman 训练集为 1 个片段、430 条样本。现有 PPO 更新采集了 32 条仿真转移。保留当前检查点、导出模型与日志作为后续对照。 [训练记录](../results/local-smoke.json)

| 目标时间 | 实验 | 验收结果 |
| --- | --- | --- |
| 11 月 26–27 日 | 用现有 `boxing.onnx` 在官方站位完成 1 局红蓝同模型对战。随后从 `model_1.pt` 用 `--policy-checkpoint` 进入 4 环境 × 8 步 × 2 次自博弈更新，保留现有内存参数与 4 环境运行图缓存。 | `match.json`、`replay.hdf5`。自博弈输出 `model_2.pt`，完成次数为 2，检查点包含初始与刷新后的两个快照，PPO/AMP 指标有限。快照间隔 1 为该小测的设置。 |
| 11 月 28–29 日 | 用已校验数据建立官方参考基线。按独立验证集重建误差选择先验并冻结解码器，监督模仿按 20 轮预算观察位置与旋转误差，再做站立预热和固定预热对手交互。若复盘暴露模仿和稳定性瓶颈，优先补有授权的 InterHuman 训练片段，按原动作组固定划分和镜像归属后重做数据校验。 | 保留模仿、站立预热、交互训练三个阶段的检查点和高层 ONNX。每阶段记录配置、种子、数据、底层版本、完成更新数、耗时与峰值。 |
| 11 月 30 日–12 月 1 日 | 通过官方 v12 验证后，让候选对固定对手互换红蓝。先用已导出的初始模型、独立保留的早期阶段模型做少量筛选。测本机完整链路，报名和本地结果就绪时进入首次线上验证。 | 记录胜平负、有效命中、倒地或 KO、仿真时长和关键回放，结合有效对局选择候选。提交物为单个上层 ONNX。 |
| 12 月 2–3 日 | 复看实际结果，复测候选。 | 留出平台验证排队时间。 |

官方参考预算是 128 环境 × 24 步采样，站立预热 32 次更新、交互训练 128 次更新。教程的交互阶段使用预热策略及其观测统计量的冻结副本，整个阶段沿用这个对手。切换训练阶段使用 `--policy-checkpoint` 初始化高层策略和观测统计量。同一 RL 阶段延长训练使用 `--resume`，`--updates` 是追加次数，运行使用新输出目录。 [官方训练和续训教程](https://github.com/HorizonRobotics/HoloMotion/blob/f52dd81ae935a828b0296f5ee0f833beb7378bf0/holoboxing/README.zh-CN.md#1-训练高层策略)

本机 GTX 1660 Ti 6 GiB 的 4 环境小测整卡显存峰值为 2,010 MiB，PPO 进程常驻内存峰值约 6.47 GiB，且初次建图曾触发 WSL 主存 OOM。小测通过后，本机可以先按累计 8 次站立更新、16 次固定对手交互的预算做一版低预算候选。设备余量支持时再增加样本量。已有授权的更大显存 Linux GPU 可以从 16 环境短跑测资源，再逐级向 128 环境扩展。先验、监督学习和 ONNX 导出也可用 CPU。 [本机峰值与修复记录](../results/README.md)

本机 11 月 26 日的首局预检遇到 WSL 冷启动错误 `Wsl/Service/CreateInstance/CreateVm/HCS/ERROR_NO_SYSTEM_RESOURCES`。在可运行 CUDA 和 Docker 的 Linux 中，使用第 4 节导出的 ONNX 启动首局。复跑时用新的输出目录。

```bash
cd "$HOLOBOXING_SOURCE"
export HOLOBOXING_IMAGE='horizonrobotics/holomotion@sha256:39015e221bdca855897ba77c5ddea28b76b91f538117cbc892ad9575aa3dcd51'
holo_model="$HOLOBOXING_RUN/boxing.onnx"
bash holoboxing/run.sh --match "$holo_model" "$holo_model" \
  --output "$HOLOBOXING_RUN/first-match"
```

对战用固定站位及版本。用 `--validate --benchmark` 记录实际显卡上的完整链路均值与 P95。初赛线上时延以官方 RTX 5090 的完整链路平均 ≤10 ms 为准。官网公布的初赛截止日为 2026 年 12 月 3 日，日窗口为北京时间 10:00–18:00，须在 18:00 前完成上传及验证。 [初赛赛程](https://hbot-competition.horizon.auto/#/home) · [赛题二规则](https://hbot-competition.horizon.auto/#/details) · [官方对战与回放](https://github.com/HorizonRobotics/HoloMotion/blob/f52dd81ae935a828b0296f5ee0f833beb7378bf0/holoboxing/README.zh-CN.md#4-本地对战与回放分析可选)
